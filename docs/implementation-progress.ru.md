## Изменение поведения частичного ESQL

Неполный бин теперь выбрасывает `UnsupportedOperationException` **до любых бизнес-действий**. Распознанные SET остаются в пооператорном отчёте и в комментариях заготовки. Они не исполняются отдельно от неподдерживаемого IF/CASE/RETURN или другого блока.

Полный перевод пока ограничен Compute/Main без параметров с `RETURNS BOOLEAN`, поддерживаемыми SET и завершающим `RETURN TRUE`. Блоки управления, другие функции, DATABASE/FILTER, JSON, namespace-пути и индексы требуют ручной реализации. Новая классификация также применяется к ESQL inventory команды analyze.

Пустой/чисто комментарийный файл не порождает исполняемую логику. Непустой неизвестный исходник и некорректные блоки диагностируются как ошибки разбора. Полного ESQL AST и трансляции условных операторов в этой итерации нет.

## Контракт XML-профиля

- Тело для generated Compute/Route — строковый XML. XPath-переменные `$Body` и `$Root/XMLNSC|XMLNS` привязываются к XML-документу.
- `First` выбирает первую подходящую строку filterTable; `All` — каждую подходящую строку, включая несколько строк на один терминал. Если режим отсутствует, используется All.
- Для All ветви получают отдельные Exchange-копии исходного строкового тела; изменение первой ветви не меняет условия следующих.
- Неизвестный режим, синтаксическая ошибка XPath, неподдерживаемая переменная, namespace-префикс или переход к родителю дают `NOT_SUPPORTED` и явную ошибку при исполнении; Default не подменяет неизвестное условие.
- ESQL-путь после XMLNSC включает XML-корень: `Order.Status` изменяет `<Order><Status>…`. Пустое тело, несовпадение корня и неподдерживаемые namespaces/пути отклоняются.
- Снимок copy локален одному вызову Compute, очищается после ошибки и изолирован для вложенных/параллельных вызовов. Изменяемые объекты внутри тела/заголовков глубоко не копируются: текущий профиль предполагает String и скалярные значения.

## Автоматическая проверка

Команда из корня: `mvn -B verify` с JDK 25.

Первая итерация: **150 тестов: 115 converter + 35 runtime; failures/errors/skipped — 0.**

После B1: **206 тестов: 156 converter + 50 runtime; failures/errors/skipped — 0** (`mvn -B verify`).

Новые проверки включают:

1. Генерацию во временный каталог всех трёх корпусов и дополнительного поддерживаемого Compute; компиляцию generated Java на фактическом runtime classpath.
2. Загрузку именно свежих классов: сохранённые generated-классы родительского classloader не могут подменить результат.
3. Пять исходных JMS-сценариев corr-01/corr-02 через embedded Artemis с отдельными именами очередей, точным сравнением тела/приоритета/меток и отсутствием неверных либо повторных отправок.
4. Отказ частичного corr-03 до изменения тела/заголовков; успешное исполнение generated XML SET и повторного копирования.
5. Девять runtime-проверок generated Route: First/All, Default, пересечение условий, повторные терминалы, повреждённые выражения и DTD.
6. Семнадцать helper-тестов XML/copy, включая вложенные и параллельные Compute-вызовы.

Focused-запуск runtime-тестов с зависимым модулем:

```bash
mvn -pl runtime -am test \
  -Dtest=GeneratedArtifactsTest,GeneratedRouteSemanticsTest,AbstractComputeBeanTest \
  -Dsurefire.failIfNoSpecifiedTests=false
```

IBM MQ/ACE и нагрузочные испытания не выполнялись. Artemis проверяет JMS-контракт примеров, а не полное поведение IBM MQMD.

Проверка включает 15 новых runtime-сценариев графа. В частности: для Route All первая подходящая строка успевает отработать до ошибки вычисления следующей; First не вычисляет ненужную строку после первого совпадения. Ошибка бизнес-ветки обрабатывается внешним catch, а не Failure узла Route.

Для fan-out выбран детерминированный последовательный порядок связей из исходника, без параллельного исполнения. Каждая ветвь получает копию исходного Exchange/строкового тела. Это договорённость профиля миграции: порядок, не гарантированный IIB, нельзя использовать как доказанный бизнес-контракт. См. [IBM: connecting message flow nodes](https://www.ibm.com/docs/en/app-connect/11.0.0?topic=content-connecting-message-flow-nodes). Обновлённые XML с MessageSnapshots требуют runtime этой версии.

### Ограничения B1

- Пока поддерживается подпоток с одним Input и одним Output и не более одной пропагацией на вызов. Несколько терминалов, fan-out и многократное All внутри подпотока явно диагностируются. Если путь не достиг Output, родительское продолжение не выполняется.
- MQInput.failure относится к ошибкам чтения/доставки транспорта и сейчас явно не поддерживается. См. [IBM: handling errors in message flows](https://www.ibm.com/docs/en/integration-bus/10.1?topic=flows-handling-errors-in-message). Его нельзя корректно заменить обычным doCatch над бизнес-маршрутом. Другие неизвестные терминалы тоже дают диагностику вместо потери рёбер.
- Синтаксически корректная неизвестная нода сохраняет статус unsupported и заготовку. Strict-режима промышленной готовности ещё нет.
- Конфликтующие Java-имена модулей пока не переименовываются автоматически: пакет блокируется с указанием источников. Это сохраняет данные и исключает выбор случайного победителя; полной стратегии namespace generated packages ещё нет.
- В parser IR пока нет полного SourceRef с диапазоном строки/столбца. Диагностика содержит источник/узел и причину; публичный Project IR/resolver и ограничения размеров/глубины остаются доработкой.

### Manifest и регенерация

В output создаются `.iib-camel-convert.tsv` и/или `.iib-camel-analyze.tsv`. Они хранят имена и контрольные суммы результатов соответствующей команды. Повторный запуск обновляет только свои неизменённые generated-файлы. Устаревший неизменённый результат удаляется; посторонние файлы сохраняются. Ручное изменение generated-файла блокирует публикацию до записи нового набора, без молчаливой перезаписи.

Для каталога, созданного старым конвертером без manifest, совпадающий файл можно принять без изменения. Отличающийся файл автоматически не присваивается конвертеру: используйте новый каталог вывода или заранее сохраните ручные изменения. Запись отдельного файла выполняется через временный файл и rename; общей файловой транзакции для всего каталога при сбое ОС нет.

Коллизии идентичности выявляются до публикации маршрутов/классов: формируется отчёт с ошибками, пакет возвращает код 3. Ошибки структуры графа создают диагностируемую fail-fast заготовку и ненулевой код, не запускающий бизнес-узлы. Обычные partial/unsupported без ошибки структуры сохраняют прежнюю политику exit 0; это код обработки, а не готовности к deployment.

## Исправление Mermaid после ручной проверки

Подписи подпотоков в форме `[[...]]` выводились без кавычек. Добавляемый суффикс `(subflow)` воспринимался как синтаксис и приводил к ошибке разбора. Теперь текст всех узлов заключён в кавычки, в том числе внутри `[["..."]]`, согласно [правилам Mermaid](https://mermaid.js.org/syntax/flowchart.html#special-characters-that-break-syntax).

CLI-регрессия анализирует настоящий `examples/analyze/system/OrderIntake.msgflow` в LR и TB и сверяет `.mmd` со схемой внутри Markdown. `mvn -B verify`: **208 тестов: 158 converter + 50 runtime; failures/errors/skipped — 0**. Дополнительно Mermaid 11.4.1 в отдельном headless Chrome воспроизвёл ошибку старой строки и успешно разобрал/отрисовал 12 свежих схем `.md`/`.mmd` демонстрационного набора и тестового корпуса. Эта проверка Mermaid выполнялась отдельно от Maven.

## Пилотный профиль B2/C1/C2 — 23 октября 2026 года

Чистая сборка `mvn -B clean verify` на JDK 25 с включёнными проверками внешнего Artemis завершилась успешно: **257 тестов, 250 успешны, 7 пропущены, failures/errors — 0** (172 converter + 85 runtime). Пропущены только опциональные сквозные IBM MQ тесты. Выполнены все 7 тестов внешнего persistent Artemis, 7 встроенных сценариев доставки и 3 проверки IBM MQ client/config.

**B2, ESQL (BUG-02/13, частично).** Добавлен ограниченный перевод IF/ELSEIF/ELSE и выражений с типами, `NULL`, логическими операциями с коротким вычислением, сравнениями и некоторыми явными `CAST`. Нераспознанные конструкции остаются неподдерживаемыми и исключают полный статус. Вне профиля остаются `CASE`, циклы, ранние `RETURN`/`RETURN FALSE`, `PROPAGATE`, FILTER/DATABASE, арифметика, полный набор выражений и полный контракт InputRoot/OutputRoot/Compute Mode; `CAST` реализован лишь для ограниченного набора типов и случаев.

**C2, схемы, модели и Mapping (BUG-10 и FR-4, частично).** Добавлены генерация JavaBean-моделей для подмножества XSD и JSON Schema и обработка локальных XSD include/import. Native IBM `.map` поддерживает простые перемещения XMLNSC-полей одинакового скалярного типа через MapStruct и сгенерированный XML processor. Это не полный ULM или Mapping: повторяющиеся/рекурсивные и многие другие конструкции схем, преобразования типов, константы, вычисляемые/условные правила и несколько источников или приёмников остаются вне профиля. Сгенерированные модели и MapStruct-мапперы проверены компиляцией; runtime-тесты загружают свежий mapper через Spring и выполняют преобразование XML → JavaBean → MapStruct → XML в Camel. Для конструкций за пределами подмножества эквивалентность не заявляется.

**C1, готовность и runtime (BUG-07/15, FR-R4/R5, частично).** В `convert` добавлен strict readiness gate по умолчанию и явный `--no-strict`; `analyze` получил режим строгой проверки готовности. В runtime добавлены конфигурационные профили Artemis и IBM MQ, JMS retry/DLQ policy и deployment-материалы. IBM MQ остаётся опциональным Should и не блокирует Artemis-пилот. На встроенном и внешнем Artemis проверены rollback отправок, повторная доставка исходного сообщения, успешный retry, локальный catch, ошибка catch, direct-вызов и отказ DLQ. При исчерпании попыток следующая доставка атомарно переводит исходное сообщение в DLQ; бизнес-ветвь повторно не вызывается. Сквозная интеграция IBM MQ, TLS и полная совместимость MQMD требуют отдельной проверки.

**Имена и структура проекта (BUG-08/10/14, частично).** Добавлена нормализация Java-идентификаторов для моделей; структурная валидация и namespace-aware разбор сохраняют ранее закрытую часть BUG-14. Полные SourceRef с позициями строк/столбцов и публичные Project IR/resolver ещё отсутствуют.

Остаются также ограничения B1: подпоток поддерживает один Input и один Output и ограниченное число пропагаций; `MQInput.failure` не поддержан; несколько терминалов и неоднозначные/конфликтующие имена диагностируются, а не разрешаются общей стратегией. Общий CLI-контракт и готовность для произвольного проекта требуют дальнейшей проверки. В частности, пока нет общей compile/load-валидации каждого результата в самом CLI. Исторические тестовые числа выше относятся к ранее завершённым итерациям, а не к текущим изменениям. Текущий [профиль пилота](pilot-profile.ru.md) задаёт критерии проверки; инструкции стенда находятся в [deployment-гайде](../deploy/README.ru.md).

Исправление регрессии доставки: corr-02 содержит неподдерживаемый Trace. Свежий маршрут останавливает подпоток, восстанавливает снимок входа и отправляет сообщение в `ORDERS.ERROR.Q`. Старые ожидания успешного `ORDERS.OUT` заменены проверками очереди ошибок, исходного тела, приоритета и отсутствия изменённого `CommentField`; отдельно проверяется отсутствие лишних доставок. Сохранённый runtime-маршрут синхронизирован со свежей генерацией. Позитивные подпотоки покрываются отдельными графовыми runtime-тестами.

Статус baseline BUG-04, 07, 08, 10, 14 и 15 остаётся частичным; остальные исправления из A1–A4/B1 перечислены выше как выполненные в их ограниченном профиле. Полный список исходных наблюдений сохранён в датированном [анализе проекта](project-analysis-2026-10-22.ru.md).

Оставшиеся пакеты исходного плана: завершение B1 (SourceRef/IR/resolver и сложные подпотоки), расширение B2 и C2 по реальному корпусу, D1 (Filter/Throw/Validate/TryCatch, выбранные HTTP/File/JMS), D2 (метрики, correlation, shutdown, внешние маршруты и поставка generated library/полный CI-конвейер). Пакет E (Database, aggregation/resequence/timeouts, SPI, web UI/hot reload) остаётся дальнейшим расширением.

## Разделение runtime и конвертера — 23 октября 2026 года

Runtime выделен в самостоятельный Maven-проект для Java 21, Spring Boot 4.1.2, Apache Camel 4.22.2 LTS и Jackson 3 XML; конвертер и legacy runtime для compatibility-тестов остаются на Java 25. Корневой Maven-агрегатор содержит `converter`, `runtime` и `compatibility-tests`; legacy runtime находится только внутри последнего. Новый runtime разбит на `runtime-core`, `runtime-delivery`, `modules/example-module` и `runtime-app`.

Основной режим доставки требует PostgreSQL: входной inbox, бизнес-изменения и события outbox фиксируются одной транзакцией, после чего вход подтверждается брокеру. Отправитель получает запись по lease и отмечает её `PROCESSED` после подтверждения брокера; сбой в промежутке допускает повторную отправку, поэтому доставка at-least-once и получателям нужна дедупликация. Планировщик отправителя выключен по умолчанию. Профиль `offline` запускает приложение без подключения к базе; коннекторы и примерный модуль также выключены без явной настройки.

CI разделён на runtime-проверку под JDK 21 с PostgreSQL 18 и converter/compatibility-проверку под JDK 25. Конфигурация workflow и README обновлены.

Реализованы независимые Camel-компоненты `artemis`, `ibmmq`, `kafka`, транспортные отправители с ожиданием подтверждения и конфигурация TLS/SASL. Добавлены JDBC/Hikari/Flyway, inbox/outbox с `SKIP LOCKED`, lease/token, повторными попытками и ограничением числа попыток. Пример модуля регистрируется через Spring AutoConfiguration и загружает собственные XML-маршруты; чужие и повторные route ID отклоняются. Выходы задаются списком неизменяемых сообщений из Java-обработчика. Полный перенос ESQL, MQRFH2 и бизнес-контрактов эта итерация не реализует.

При ревью исправлен риск пропуска первого незафиксированного Kafka сообщения новой consumer group: задан `autoOffsetReset=earliest`. Реальный Kafka consumer проверен с отказом принятия в БД: до успешного коммита inbox/outbox offset отсутствует, сообщение повторяется и затем подтверждается. В IBM MQ TLS исправлено сохранение JVM client keystore при явном truststore; TLS handshake и реальный IBM MQ пока не проверены.

Проверки на настоящем **JDK 21.0.13**: `mvn -B -f runtime/pom.xml verify` — **52 теста, 0 failures/errors/skipped** с локальными PostgreSQL 18, Artemis и Kafka. Среди них 13 транзакционных PostgreSQL-проверок, реальные отправители двух брокеров, Artemis → XML-модуль → READY → Kafka → PROCESSED и восстановление Kafka после отказа БД. Проверены запуск готового JAR, HTTP health/readiness (`UP`) и Prometheus endpoint. Копия `runtime/` отдельно от репозитория, конвертера и корневого POM также успешно собирается на JDK 21.

Общий `mvn -B verify` на JDK 25 — **309 тестов, 0 failures/errors, 31 gated-проверка внешних сервисов пропущена**. Из них 17 проверок нового runtime отдельно выполнены в указанном выше запуске JDK 21; 14 относятся к прежним внешним Artemis/IBM MQ compatibility-тестам. Существующие 257 converter/compatibility-тестов сохранены. Руководства legacy среды обновлены на новый каталог и отделены от инструкций самостоятельного runtime.

Текущие эксплуатационные границы: at-least-once, отсутствие общего порядка между брокерами, подбор lease под размер пакета и время отправки, настройка карантина источников для каждого модуля. Автоматическая очистка inbox/outbox, административный повтор FAILED и бизнес-реализации модулей ещё не добавлены. Полный контракт — [доставка](../runtime/docs/delivery.ru.md), добавление модулей — [шаблон](../runtime/docs/module-template.ru.md).
