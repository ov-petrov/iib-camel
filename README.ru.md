# iib-camel

Инструмент миграции приложений с IBM Integration Bus (IIB / IBM App Connect Enterprise, ACE)
на современный Java-стек на базе **Spring Boot** и **Apache Camel**.

> 🇬🇧 English version: [README.md](README.md)

## Назначение

На вход инструменту загружаются артефакты приложений Legacy-интеграции на IBM Integration Bus:
потоки сообщений (`.msgflow`), подпотоки (`.subflow`), модули ESQL (`.esql`), наборы сообщений
(`.mset`, схемы XSD/DFDL/JSON).

На выходе формируются артефакты для приложения на Spring Boot + Apache Camel:

- **маршруты Apache Camel** в формате XML DSL;
- **Java-классы** для преобразования сообщений;
- **классы мапперов MapStruct**, сгенерированные по логике Compute / Mapping / ESQL;
- каркас конфигурации (`application.properties` / `application.yml`).

Инструмент не заменяет разработчика, но снимает основную рутину миграции: скелеты маршрутов,
связывание узлов, заготовки маппингов и преобразований формируются автоматически, после чего
разработчик дорабатывает и валидирует бизнес-логику.

## Как это работает

Конвейер миграции:

```
 ┌───────────────┐   ┌──────────────┐   ┌───────────────┐   ┌──────────────┐
 │ Артефакты IIB │ → │    Разбор    │ → │ Промежуточная │ → │  Генерация   │
 │ .msgflow      │   │  (XML, ESQL) │   │  модель (DOM) │   │ (маршруты,   │
 │ .subflow      │   │              │   │               │   │  мапперы)    │
 │ .esql         │   └──────────────┘   └───────────────┘   └──────────────┘
 │ наборы        │           │                                        │
 │ сообщений     │           │              ┌───────────────┐         │
 └───────────────┘           └── отчёт ────────────────────────────────────┐
                               о проблемах      │  Валидация  │ ←── для ручной
                                                └───────────────┘     доработки
```

1. **Разбор (парсинг)** — чтение и валидация файлов проекта IIB, построение промежуточной модели
   (внутреннее представление потоков и преобразований).
2. **Трансформация** — сопоставление узлов IIB элементам Apache Camel (см.
   [функциональные требования](docs/functional-requirements.ru.md)).
3. **Генерация** — вывод маршрутов Camel в XML, Java-классов, мапперов MapStruct, конфигурации.
4. **Отчёт** — отчёт о миграции: что сконвертировано, какие узлы требуют ручной доработки.

## Состав продукта и структура репозитория

Проект собран как multi-module Maven с двумя независимыми приложениями:

```
iib-camel/
├── pom.xml        ← родительский (агрегатор): одна сборка Maven на оба модуля
├── converter/     ← one-shot CLI: артефакты IIB → Camel XML DSL + Java + MapStruct + отчёт
└── runtime/       ← Spring Boot сервис, исполняющий конвертированные маршруты Camel
```

```
конвертер (запускается по команде, завершается)   runtime (работает постоянно)
        │                                                ▲
        ▼                                                │
   маршруты Camel XML, Java, MapStruct  ── при деплое (jar/classpath) ┘
```

- **конвертер** — отдельное one-shot Java-приложение: запускается по команде, конвертирует указанные
  артефакты и завершается, не оставляя фоновых процессов и веб-служб; используется инженерами и CI/CD.
- **runtime** — *сервис, на котором после конвертации всё работает*: Spring Boot + Apache Camel,
  маршруты загружаются из `runtime/src/main/resources/camel/*.xml` (classpath) либо из внешнего
  каталога, адаптеры IBM MQ (`camel-jms`), единая обработка ошибок, health/metrics.

## Основные возможности

- Разбор файлов `.msgflow`, `.subflow`, `.esql` и наборов сообщений;
- Пакетная конвертация всего проекта IIB или выбранного каталога;
- Разворачивание подпотоков во вложенные шаги целевых маршрутов;
- Перевод ESQL: выражения, предикаты, фрагменты `WHERE` и `SET`;
- Генерация мапперов MapStruct по логике преобразования сообщений;
- Отчёт о миграции со списком неконвертируемых элементов и требуемых ручных доработок;
- Трассируемость: сгенерированные элементы содержат ссылки на исходный поток и исходный узел.

Подробные требования описаны в [Функциональных требованиях](docs/functional-requirements.ru.md),
[Functional requirements](docs/functional-requirements.en.md) (English).

## Технологический стек

| Слой                  | Технология                                        |
|-----------------------|----------------------------------------------------|
| Язык                  | Java 25                                            |
| Сборка                | Maven (multi-module)                               |
| Конвертер             | Java 25 CLI (отдельное one-shot приложение)        |
| Runtime-сервис        | Spring Boot 4.x + Apache Camel 4.x (XML DSL)       |
| Маппинг сообщений     | MapStruct (генерируется как Spring-бин)            |
| Тестирование          | JUnit 5, golden-файлы, встроенный брокер Artemis   |

требования (MoSCoW) и стратегия тестирования зафиксированы; реализация конвертера — на старте.
